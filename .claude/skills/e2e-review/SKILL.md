# E2E Review

Review test implementations from **`/playwright-mcp`** (Generator/Healer) before merge or grading.

Works in **Cursor** and **Claude Code** (same skill via `.claude/skills` symlink).

**Checklist:** [references/checklist.md](references/checklist.md)  
**Architecture source:** [../playwright-mcp/references/rules.md](../playwright-mcp/references/rules.md)  
**Diff workflow reference:** `e2e-diff-review.mdc` (branch confirmation pattern)

---

## Step 0: Confirm review scope

When `/e2e-review` is invoked, ask what to review:

```text
How should I review?

a. Specific files (paste paths)
b. Git diff (branch vs base — I will ask for branches)
c. All changed E2E files since last commit
d. Latest playwright-mcp output (you describe or paste paths)
```

Use **AskQuestion** when available; otherwise ask conversationally and **wait**.

---

## Step 1: Branches — stop and ask first (diff reviews only)

**Do not** run `git diff` until branches are confirmed. Pattern from `e2e-diff-review.mdc`:

### When user picks git diff without naming branches

Ask in **one message**, then **wait**:

1. **PR base** — branch the PR targets (e.g. `main`, `develop`) → `origin/<base>`
2. **Working branch** — branch with commits; offer: “If unspecified, I’ll use `git branch --show-current` — reply **yes** to confirm or send the branch name.”

**Never** silently assume `origin/main` or `origin/develop`.

Accept shortcuts: `base: develop`, `e2e review — base main`, `current: feature/foo | base: develop`.

### After confirmation

```bash
git fetch origin <base-branch>   # when needed
git diff --stat origin/<BASE>...HEAD
git diff --name-only origin/<BASE>...HEAD
```

**Focus paths:** `src/tests/**`, `src/modules/**`, `src/pages/**`, `src/fixtures/**`, `src/utils/**` touched for E2E.

---

## Step 2: Automated gates (always run)

```bash
npm run rules:check
npm run build
```

Include all rule-engine violations in findings. Fix suggestions must preserve **Pages → Modules → Tests**.

---

## Step 3: Manual review — four pillars

Walk [references/checklist.md](references/checklist.md) sections **1–6**. The four required pillars:

### 1. Architecture

- Tests → Modules → Pages (never skip layers)
- No `page.locator()` in modules; no `@pages/` in specs
- Pages: arrow-function locators, no business logic
- Matches `/playwright-mcp` constraints

### 2. Naming & placement

- `*Page.ts` in `src/pages/`, `*Module.ts` in `src/modules/`, `{kebab}.spec.ts` in `src/tests/`
- Tags in describe: `@P0` / `@P1` / `@P2` / `@Smoke` / `@Regression`
- Path aliases `@pages/`, `@modules/`, `@utils/`

### 3. Locator priority (page objects only)

Flag violations in priority order (prefer higher when DOM allows):

| Priority | Strategy |
|----------|----------|
| **a** | `data-testid` / `data-testvalue` |
| **b** | `id`, `name` |
| **c** | Playwright (`getByRole`, `getByLabel`, `getByPlaceholder`, …) |
| **d** | CSS selectors |
| **e** | XPath (last resort) |

Example **Fail:** XPath on an element that has `data-testid` in the requirement ticket or DOM.  
Example **Partial:** CSS `#submit` when `getByRole('button', { name: 'Submit' })` is stable.

### 4. File length

| File | Warn | Fail |
|------|------|------|
| `*Page.ts` | 201–280 lines | > 280 |
| `*Module.ts` | 151–220 lines | > 220 |
| `*.spec.ts` | 151–220 lines | > 220 |
| Method | 21–35 lines | > 35 |

Recommend splits (e.g. sub-page objects, extracted module workflows) when over limits.

---

## Step 4: Optional checks

Only when useful and paths are in scope:

```bash
npx eslint src/tests/<file>.spec.ts src/modules/<file>.ts src/pages/<file>.ts
```

Lint **diff files only**; if `xargs` fails, lint each changed file individually.

If `requirements/{module}.md` exists, verify scenario coverage (checklist §6).

---

## Step 5: Report

Output using the template in [references/checklist.md](references/checklist.md):

- **Pass / Partial / Fail** per section
- **File paths + line references** for every finding
- **Concrete fix** (not vague “improve locators”)
- **Summary table** at top

### Tone

Concise; prioritize **risks and checklist gaps** over repeating the whole diff.

### Verdict

| Overall | When |
|---------|------|
| **Approve** | All sections Pass; rule engine clean |
| **Approve with nits** | Partials only; no Fail |
| **Request changes** | Any Fail in architecture, naming, or locators |
| **Block** | Rule engine fail + architecture Fail |

---

## Step 6: After review

If **Request changes** or **Block**:

1. List minimal patches (Healer-sized, not full rewrite)
2. Suggest `/playwright-mcp` Healer with this review output as input
3. Re-run `/e2e-review` after fixes

Do **not** rewrite implementation unless the user asks.
