Architecture

Layering

Tests (src/tests/*.spec.ts)
  → Modules (src/modules/*Module.ts)
    → Pages (src/pages/*Page.ts)

Tests call modules and fixtures. Modules orchestrate one or more pages. Pages wrap Playwright's Page API. No layer calls past the one directly below it.

Folders

FolderRole
src/pagesLocators + thin actions, one class per screen/component
src/modulesUser-facing workflows built from pages
src/testsSpecs — tagged, use test.step(), call modules/fixtures only
src/fixturesPlaywright fixtures wiring pages/modules/auth into test
src/apiTyped REST clients for API-level setup/assertions
src/configEnvironment-driven config (from .env.local)
src/testdataStatic fixtures/types for test data
src/utilsLogger, wait helpers, data generators, reporter

Quality gate

The rule engine (rules/framework-rule-engine.json + scripts/rule-engine.js) enforces file placement, naming, and the constraints above. It runs via npm run rules:check, in .husky/pre-commit (staged files), and in CI (changed files).

Claude Code integration

.claude/skills/ ships five skills used by the colleague workflow: setup-framework, generate-test-cases, create-md-ticket, playwright-mcp, e2e-review. Playwright MCP is wired via the project .mcp.json; Chrome MCP comes from claude --chrome.
