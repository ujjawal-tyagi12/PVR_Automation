Section 02

Failures — 20 raw, reclassified to 2

The first parallel run's 20 failures collapse into three groups once each is re-run alone: one real, now-fixed bug; two still-open findings; the rest confirmed parallel-load flakes.

Fixed during this run
ProfileEditPage.ts — email-verify locator ambiguity (7 tests). The emailVerifyButton locator (getByRole('button', { name: /^verify$/i })) started resolving to 2 elements — the real email-verify button, and an unrelated amber "Verify" button elsewhere on the page. Every test calling clickVerifyEmail() hit a Playwright strict-mode violation. Rescoped the locator to the form-item container wrapping the email textbox. All 7 verified passing post-fix; npm run build and npm run rules:check (127 files) both clean.

Section 04

Coverage gap — Social Login not automated

One full module from the M2 sheet has no ticket and no test anywhere in this repo.

gap · TC_ADM_093–104

The sheet's Social Login section — Sign in with Google/Apple, OAuth flow initiation, the "Missing Details" pre-population screen, mobile-number-conflict during social login, future social logins skipping Missing Details, GA4 tracking, URL masking, responsiveness, retry-on-failure, and the WhatsApp opt-in default — has zero dedicated tickets or tests. No requirements/*.md file and no TC_ADM_09[3-9]/TC_ADM_10[0-4] reference exists in any spec file.

The concept is partially represented under register-login.spec.ts's own generated scenarios (REG-009/010/011/028/033/034/037, all counted in §3's skip table above), but those don't map 1:1 to the sheet's IDs or scenarios, and all 7 are blocked pending live OAuth grounding.

Recommend ticketing this properly via /generate-test-cases against TC_ADM_093–104 before considering M2 fully covered.

Bottom line

  • 180/212 (85%) of M2's live tests pass. One real bug — the profile-edit email-verify locator ambiguity, 7 tests — was found and fixed in this pass, verified clean against build and rules:check.
  • 2 tests remain genuine open findings (TC_ADM_090, REG-036) — reproduce reliably, root cause not yet pinned down, flagged for a live-grounding follow-up rather than more headless retries.
  • 30 skips are all environment/access/OAuth/hardware limits or confirmed-live product findings — including a real GA4 tracking regression shared across 3 tests — not missing test-authoring effort.
